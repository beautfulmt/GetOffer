# 面试录音与文字稿复盘

目标是逐题给出可练的完整改进答法，并识别哪些确认素材可回写简历。与[真实性规则](truthfulness.md)共同使用。

## 先确认输入能否读取

有文字稿就直接读，不要求用户重新转写。有音频时按以下顺序选择：

1. **宿主可直接理解音频：**读取实际文件，确认可听范围和清晰度。
2. **不能直接理解：**检查当前已可用的本地转写、连接器或有音频工具的 Agent。只有实际具备能力且数据边界合适时才调用。Agent 的模型与推理配置沿用宿主，不把普通文本 Agent 当成转写能力。
3. **仍无可用能力：**说明已能确认的文件状态与缺少的能力，请用户提供文字稿，或用其选择的转写工具处理后发来。不能只根据文件名猜面试内容。

本地处理优先。外部转写会发送录音时，先说明发送到哪里、什么内容，并获得用户同意；泛泛的“帮我复盘”不等于同意上传。没有转写能力时，不自动安装大型模型或索取 API Key。音频很短、静音、损坏或无法辨认时如实说明。

采用工具或 Agent 时，确认实际返回了内容再使用。报告注明来源是原音频、自动转写还是用户稿，转写错误和不确定的内容保持标记。

## 还原问答

- 区分面试官和候选人，按 Q01、Q02 等编号整理问题与对应回答。
- 仅在音频或稿件提供可靠时间信息时写时间定位；纯文本用问答编号或段落位置，不补造时间戳。
- 标出“说话人待确认”“听不清”“问题未完整提供”。只追问影响评价的关键歧义，能判断的其他题继续做。
- 长稿按实际顺序分段，保留已覆盖和未覆盖的题目范围。未读完整段材料时，不称为全量复盘。

## 逐题复盘

每道已识别的问题都输出以下内容，使用[复盘模板](../assets/review-template.md)：

1. **面试官在问什么：**依据原问题解释想核实的任务、知识或经历，属于推断时明说。
2. **你当时怎么答：**引用原句或忠实概括，保留个人贡献、数字和不确定性。
3. **问题在哪：**具体指出漏答、证据缺口、逻辑跳步、贡献边界或表达问题，并引用对应位置；不只写“结构不够好”。
4. **更好的完整答法：**按[可练回答规则](answer-coaching.md)直接回答该问题。采用已确认事实；对用户提交的清晰原答可做忠实表达整理，注明材料依据，不能将整理稿自动视为已核实新经历。待确认项单列，不把核验话术写进回答。
5. **下一次怎么练：**给一个对应的追问或练习动作。

答得好的题也解释有效之处。没有明显问题时，可以给更简洁的版本，保留用户原有判断。不能仅凭一段回答给人格、潜力或录用结果下结论。

每题按问题的实际复杂度展开，不要求五个部分等长。清晰题用短反馈和完整回答，复杂题再解释推理。复盘结尾集中核对当前最关键的一段经历，避免每题附三问或重复隐私提醒。

若涉及知识题，先区分表达错误与知识本身的错误，必要时查当前可靠资料。对未提供的业务内幕和面试官动机保留未知。

## 这些内容可以写进简历

独立列出候选清单：来自哪一题、原话是什么、对应哪段经历、拟增加或改写什么、是否需要确认。

- 原简历没写、面试中说清的个人动作或难点，可以成为补充候选。
- 团队成果、估算、转写疑点或与旧稿冲突的数字，需要先核对归属与依据。
- 导师给出的更好答法、教学示范或未来改进计划，不构成新经历。

用户确认后，先更新经历库事实及来源，再更新授权的简历版本，保留旧稿和修改记录。用户本轮已经明确确认了具体事实并要求更新时，继续完成，无需逐文件重复确认。只有“帮我复盘”时，先交付候选清单，不自动改简历。

确认清单区分事实确认与文件修改范围：已由用户明确认可准确的原话不要求逐条重述；仍有冲突或转写疑点的事实集中核对。用户只授权部分回写时只处理那部分，其他岗位受影响的版本记为需同步。

## 交付与收尾

报告包含材料范围、逐题复盘、可回写清单，以及最值得先练的一两个点。自动转写不确定性和仍缺的资料就近说明。

允许保存时写到个人 `interviews/`；原录音按用户指定的位置保留，避免无必要复制或公开。用户要求不保存时只在当前对话交付，不创建档案或报告文件。

回写得到整份可投递新版时按[交付规则](delivery.md)更新对应文件，避免只有 Markdown 已改而投递 PDF 仍是旧版。更新任务记录中的报告、当前简历和下一次练习。

# 面试录音与文字稿复盘

目标是按这一轮的标准判断表现，逐题给出可练的完整改进答法，说清下一轮怎么准备，并识别哪些确认素材可回写简历。与[真实性规则](truthfulness.md)共同使用。

## 先确认输入能否读取

有文字稿就直接读，不要求用户重新转写。有音频时按以下顺序选择：

1. **宿主可直接理解音频：**读取实际文件，确认可听范围和清晰度。
2. **不能直接理解：**检查当前已可用的本地转写、连接器或有音频工具的 Agent。只有实际具备能力且数据边界合适时才调用。Agent 的模型与推理配置沿用宿主，不把普通文本 Agent 当成转写能力。
3. **仍无可用能力：**说明已能确认的文件状态与缺少的能力，告诉用户怎样得到文字稿（见下），请其处理后发来。不能只根据文件名猜面试内容。

本地处理优先。外部转写会发送录音时，先说明发送到哪里、什么内容，并获得用户同意；泛泛的“帮我复盘”不等于同意上传。没有转写能力时，不自动安装大型模型或索取 API Key。音频很短、静音、损坏或无法辨认时如实说明。

采用工具或 Agent 时，确认实际返回了内容再使用。报告注明来源是原音频、自动转写、用户文字稿还是回忆稿，转写错误和不确定的内容保持标记。

### 文字稿从哪来

- **有录音：**手机录音应用自带的转文字、会议软件的录制与转写，或常见的转写工具（如飞书妙记、通义听悟）都可以。由用户自己选择工具并上传，技能不替用户上传。
- **没有录音：**请用户尽快凭回忆按“题目 → 我大概怎么答的 → 面试官的反应或追问”逐题写下来，记不全的题写个大概也有用。报告里标明这是回忆稿，原话可能有出入，点评以内容和思路为主，不纠结措辞。
- 提醒一句：录音前留意对方是否允许，材料只用于个人复盘。

## 先建立评价基准

同样的回答，放在业务一面和终面里评价不同。复盘前读取对应岗位的 JD、当时投递的简历版本和经历库，并确认[轮次](interview-rounds.md)。轮次优先从用户的话、文字稿内容（如面试官的自我介绍、问题类型）和任务记录里判断；判断不了且会影响结论时反问一次，仍不清楚就说明按哪一轮的标准评。

没有 JD 或简历时如实说明评价基准有限，照常逐题复盘。

## 还原问答

- 区分面试官和候选人，按 Q01、Q02 等编号整理问题与对应回答。
- 仅在音频或稿件提供可靠时间信息时写时间定位；纯文本用问答编号或段落位置，不补造时间戳。
- 标出“说话人待确认”“听不清”“问题未完整提供”。只追问影响评价的关键歧义，能判断的其他题继续做。
- 长稿按实际顺序分段，保留已覆盖和未覆盖的题目范围。未读完整段材料时，不称为全量复盘。

## 整体评价

放在逐题之前，形式与模拟面试一致：按本轮的标准给一句话结论；三种处理标签各几题；最突出的一两个优点和最要害的一两个问题，分开写、各附题号，问题要说明对面试官判断的影响；最该先改的三题，每题附为什么先改。不打分、不给总评等级，不预测面试结果，不凭回答评判人格或潜力。

## 逐题复盘

目标是让用户一眼看出每道题哪里答得好、哪里要改、怎么改。按[复盘模板](../assets/review-template.md)输出：一个主问题一题，追问写在同一题的对话里，追问换了话题才另起一题；事务性问答合进相邻一题或材料说明，不单独成题。每题包含：

1. **处理标签：**`答得好`、`需补强`或`要重练`，定义见[面试报告的网页版](report-html.md#每道题怎么呈现)。标签只给练习排优先级，不是分数或等级。
2. **面试官想考察：**每题都写，一到两项，依据原问题和本轮侧重推断，属于推断时明说。
3. **你的回答：**按顺序写出每一轮的完整回答，只删口头语、重复和与点评无关的枝节，不改意思，不能只摘一句；保留个人贡献、数字和不确定性。后面点评到的每一处都要在这里看得到。值得保留的说法和有问题的说法分别标出，有问题的编号。
4. **好在哪：**具体做法。答得好的题必须写，其他题有就写。
5. **问题在哪：**列出所有影响判断的问题，通常 1 到 3 个，不只挑一个。按编号逐条指出漏答、证据缺口、逻辑跳步、贡献边界、知识错误或表达问题，说清为什么影响判断；不只写“结构不够好”。有归属疑点时，按[把事情讲圆满](answer-coaching.md#把事情讲圆满)说明怎样在真实范围内讲完整。
6. **改进后的答法：**按[可练回答规则](answer-coaching.md)直接回答该问题，有追问时连追问的答法一起写；采用已确认事实或对清晰原答的忠实整理；建议做法写成“如果”“下次”。
7. **改了什么：**按问题编号逐条写原来怎么说 → 现在怎么说，以及为什么。答得好的题写“还能更好的一处”，不为了显得改过而重写。
8. **下次怎么练：**一个对应的追问或练习动作。

每题按问题的实际复杂度展开，清晰题用短反馈和完整回答，复杂题再解释推理。复盘结尾集中核对当前最关键的一段经历，避免每题附三问或重复隐私提醒。

若涉及知识题，先区分表达错误与知识本身的错误，必要时查当前可靠资料。对未提供的业务内幕和面试官动机保留未知。

## 下一轮怎么准备

根据这一轮暴露的问题和下一轮通常的侧重（见[各轮的题型构成](interview-rounds.md#各轮的题型构成)），给出一两个最该准备的点。例如一面里项目取舍讲得浅，而二面会深挖取舍，就先把主经历的备选方案和判断依据理清。不知道是否还有下一轮时，按最可能的下一轮给，并说明依据。

## 这些内容可以写进简历

独立列出候选清单：来自哪一题、原话是什么、对应哪段经历、拟增加或改写什么、是否需要确认。

- 原简历没写、面试中说清的个人动作或难点，可以成为补充候选。
- 团队成果、估算、转写疑点或与旧稿冲突的数字，需要先核对归属与依据。
- 导师给出的更好答法、教学示范或未来改进计划，不构成新经历。

用户确认后，先更新经历库事实及来源，再按[经历组织规则](resume-structure.md)更新授权的简历版本，避免同一事实重复出现，并保留旧稿和修改记录。用户本轮已经明确确认了具体事实并要求更新时，继续完成，无需逐文件重复确认。只有“帮我复盘”时，先交付候选清单，不自动改简历。用户只授权部分回写时只处理那部分，其他岗位受影响的版本记为需同步。

## 交付与收尾

报告包含材料来源与范围、评价基准、整体评价、逐题复盘、下一轮怎么准备和可回写清单。自动转写或回忆稿的不确定性和仍缺的资料就近说明。

允许保存的多题复盘，完整原答、逐题反馈和改进答法放在报告中，聊天默认给整体评价、最该先改的三题与其中一题的完整改写，并链接全文；用户只说“保存复盘”时按这个默认量给，不必在聊天重述报告。不能以摘要替代报告里的逐题覆盖。用户明确要求只在聊天完整查看或不保存时，完整输出其要求的题目，不强制改为文件或截短回答。

允许保存时写到个人 `interviews/`：Markdown 报告留作记录，同时按[面试报告的网页版](report-html.md)生成同名 HTML，左边原答、右边改法。材料入口和聊天先给网页链接。按下节处理脱敏。覆盖检查、原稿备份和内部记录不作为主要附件。原录音按用户指定的位置保留，避免无必要复制或公开。用户要求不保存时只在当前对话交付。

回写得到整份可投递新版时按[交付规则](delivery.md)更新对应文件，避免只有 Markdown 已改而投递 PDF 仍是旧版。更新任务记录中的报告、当前简历，下一步写下一轮最该准备的点。

### 脱敏时保留复盘依据

- 默认将不必要的面试官姓名、联系方式换成稳定的角色称呼；有多位面试官时仍区分说话人。不把公开状态未知等同于敏感，不自动删除原答里的业务数字、个人动作或判断依据。
- 用户明确要求隐藏或材料明确标为敏感的内容，用占位或概括替换具体值；保留指标口径、时间窗口、变化方向、个人与团队归属及不确定性。不编造替代数字，不用占位值计算结果；若隐藏后无法核验某个结论，就近说明该限制，不把脱敏造成的缺失算成候选人没提供证据。
- 脱敏仅影响本次报告的呈现，不覆盖原始材料，不将脱敏占位内容回写为经历事实。交付时简述实际处理一次即可；用户要求保留原文时照办，不为常规脱敏额外停下确认。

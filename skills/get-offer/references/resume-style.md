# 默认样式：墨蓝商务

新建或重新排版简历时默认使用此样式。用户指定原版、黑白、学校模板或其他视觉要求时优先遵守；只优化内容或片段时不扩大为整份换版。

## 视觉基准

白底、单栏，正文深灰；墨蓝只用于姓名、目标岗位、栏目标题、页头粗线和要点符号。通过字号、留白、日期对齐和短主题标签建立层次，不使用整块深色背景、装饰图标、技能进度条或满页表格线。

下表取自[墨蓝 HTML 模板](../assets/resume-navy.html)。用别的 PDF 或 DOCX 工具时，照它落实为段落样式与制表位，不只给默认 Markdown 导出换个蓝色标题；DOCX 正文须可编辑，与 PDF 允许合理的换行差异。

| 元素 | 设定 |
|---|---|
| 纸张与页边距 | A4，上下 14 mm、左右 15 mm；用户指定优先 |
| 颜色 | 墨蓝 `#243F5A`，正文 `#202328`，次要信息 `#646B73`，白底；待补空位和稿件提示用橙字 `#A8431B`、浅橙底 `#FBEDE6` |
| 页头 | 姓名 24 pt，左对齐；目标岗位 11.5 pt，同排右对齐，过长时自然换行；信息行 9.4 pt、灰色；页头下方 2 pt 墨蓝粗线 |
| 正文 | 中文无衬线字体 10.1 pt，行距 15.6 pt（紧凑 14.4 pt）；字号不随间距档变化，用其他工具排版时也不低于 9.5 pt |
| 栏目标题 | 10.6 pt、半粗、墨蓝，字距拉开；下方一条浅灰细线 |
| 条目 | 公司或项目名 11 pt、半粗；任职的实际岗位在下一行，9.5 pt、蓝灰 `#55708C`；项目分组名与正文同号、加粗；要点用墨蓝小方块 |
| 日期 | 9.2 pt、灰色，右对齐；长公司名或长日期换行，不互相覆盖 |
| 间距（标准 / 紧凑） | 栏目间 16 / 10 pt，栏目标题下 7 / 6 pt，条目间 10 / 7 pt，块间 4 / 3 pt，要点间 3 / 1.5 pt；紧凑档大约多放 10% 到 15% 的内容 |

字体用宿主已有、导出后文字映射准确的中文无衬线字体，例如思源黑体、Noto Sans CJK、Arial Unicode MS 或微软雅黑；不依赖某台机器的固定字体路径，也不把系统字体文件打包进技能。脚本遇到部首替代会自动换字体，用其他工具时检查实际替换效果。

## 手工填模板

PDF 首选用[交付规则](delivery.md#格式与版本)里的脚本从源稿生成，只在没法跑脚本或用户要改版式时手工填模板。能跑脚本时，可先加 `--save-html <页面>.html` 另存脚本填好的页面，改完再用 `--html <页面>.html --source <源稿>.md` 打印并核验。

- 填充姓名、目标岗位、信息行、栏目块及可选演练标记，无内容的元素删除。原始资料先转义为文本，只用自己生成的已知 HTML 结构组织内容。
- 模板占位符：`{{name}}`、`{{target_role}}`、`{{meta_lines}}`、`{{sections}}`、`{{sample_notice}}`，以及写入 PDF 标题元数据的 `{{document_title}}`。每个在模板中只出现一次，全部替换，填充后检查不再残留 `{{`。正式投递稿删除 `{{sample_notice}}`，英文简历把 `lang` 改为 `en`（脚本从源稿生成时会自动判断）。
- 模板底部注释里有填好的示意结构，照它的嵌套生成 `{{sections}}`，正式稿删除注释。类名：栏目 `.resume-section`；条目 `.entry`，条目头 `.entry-head`、`.entry-title`、`.entry-date`；任职内的实际岗位 `.entry-role`，教育补充信息 `.education-detail`，职责范围 `.scope`；项目分组 `.project` 和 `.project-title`；要点 `.points`，主题标签 `.theme`；技能段落 `.skills`；页头稿件提示 `.draft-note`，只用于待补稿、写在信息行里；待补空位 `<span class="pending">`；演练虚构提示 `.sample-notice`。
- 示意中的实习条目对应“复杂任职精选项目”，项目条目对应“直接分条”；正文结构按[经历组织规则](resume-structure.md)选择，不把示意条目整体复制进成品。
- 默认是标准间距；一页排不下时给 `<html>` 标签加 `class="compact"`，换成紧凑间距，字号不变。

## 实际排版检查

脚本不看版面长相。按[交付检查](delivery.md#以实际成品核验)打开或渲染每一页，针对本样式检查：

- 姓名和长岗位是否相撞、长公司名是否挤到日期、要点续行是否对齐，以及中文字体、数字和标点。
- 标题跟随下一段，单条要点尽量不跨页；较长任职可以在项目或要点之间分页，不能为保持整段同页制造大块空白。
- 投递稿里的空位、草稿或演练标记和样式名等内部标签由脚本 `--final` 检查。演练稿保留清楚的虚构标记，最终版用 `--final --sample` 检查，不能误称真实投递版本。

检查通过后再交付。

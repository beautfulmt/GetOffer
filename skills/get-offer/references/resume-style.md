# 默认样式：墨蓝商务

新建或重新排版简历时默认使用此样式。用户指定原版、黑白、学校模板或其他视觉要求时优先遵守；只优化内容或片段时不扩大为整份换版。

## 视觉基准

白底、单栏，正文深灰；墨蓝只用于姓名、目标岗位、栏目标题及少量细线。通过字号、留白、日期对齐和短主题标签建立层次，不使用整块深色背景、装饰图标、技能进度条或满页表格线。

| 元素 | 默认设定 |
|---|---|
| 纸张与页边距 | 中文投递默认 A4，四边约 20 mm；用户指定优先 |
| 颜色 | 墨蓝 `#243F5A`，正文 `#202328`，次要信息 `#646B73`，白底 |
| 姓名与目标岗位 | 姓名约 28 pt，左对齐；目标岗位约 11 pt，可同排右对齐，过长时自然换行 |
| 正文 | 中文无衬线字体，约 10.1 pt，行距约 17.2 pt；不为压页缩到难读，通常不低于 9.5 pt |
| 栏目与条目 | 栏目约 11.2 pt、半粗，左侧短墨蓝细线；公司或项目名约 11.2 pt，实际岗位可与公司同排或下一行 |
| 日期与辅助信息 | 约 8.8 至 9.2 pt、灰色；日期右对齐，长公司名或长日期需换行，不互相覆盖 |
| 间距 | 栏目间约 24 至 28 pt，要点间约 6 至 8 pt；同一项目的动作与结果保持接近 |

优先使用宿主已有且导出后文字映射准确的中文无衬线字体，例如思源黑体、Noto Sans CJK、Arial Unicode MS 或微软雅黑，并检查实际替换效果。不要依赖某台机器的固定字体路径，也不将系统字体文件打包进技能。

## PDF 与可编辑版本

可用 HTML 打印时，复用[墨蓝商务 HTML 模板](../assets/resume-navy.html)的样式。填充姓名、目标岗位、信息行、栏目块及可选演练标记；无内容的元素删除，所有占位符必须替换。原始资料先转义为文本，只用自己生成的已知 HTML 结构组织内容。

模板占位符：`{{name}}`、`{{target_role}}`、`{{meta_lines}}`、`{{sections}}`、`{{sample_notice}}`，以及写入 PDF 标题元数据的 `{{document_title}}`。模板底部有一段填好的示意结构，照它的嵌套方式生成 `{{sections}}`；正式投递稿删除 `{{sample_notice}}`。英文简历把 `lang` 改为 `en`。

模板栏目使用 `.resume-section`，条目使用 `.entry`，条目头使用 `.entry-head`、`.entry-title` 和 `.entry-date`；任职内的实际岗位用 `.entry-role`，教育补充信息用 `.education-detail`，职责概括用 `.scope`，项目分组用 `.project` 和 `.project-title`，要点用 `.points`，主题标签用 `.theme` 加粗，技能段落用 `.skills`，演练虚构提示用 `.sample-notice`。正文结构按[经历组织规则](resume-structure.md)选择，不能把三个示意结构都复制进成品。

宿主采用其他 PDF 或 DOCX 工具时，将同样的颜色、字体层级、间距及日期对齐落实为段落样式与制表位；不要只给默认 Markdown 导出换个蓝色标题。DOCX 正文须可编辑，与 PDF 之间允许合理换行差异。

交付时不额外倾倒 HTML、页面 PNG、构建脚本或演练记录；模板 HTML 仅用于技能复用和实际导出。

## 实际排版检查

按[交付检查](delivery.md#以实际成品核验)核对正文、纸张、页面与文字可提取性，并针对本样式检查：

- 姓名和长岗位是否相撞、长公司名是否挤到日期、要点续行是否对齐，以及中文字体、数字和标点。
- 标题跟随下一段，单条要点尽量不跨页；较长任职可以在项目或要点之间分页，不能为保持整段同页制造大块空白。
- 实际投递稿不含“墨蓝商务”等样式标签。演练稿保留清楚的虚构标记，不能误称真实投递版本。

检查通过后再交付。

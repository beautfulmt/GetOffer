# 面试报告：逐题点评与网页版

面试复盘和模拟面试点评共用这份规范。保存时交两份同名文件：Markdown 报告留作记录和后续引用，网页版左边原答、右边改法，给用户看。不保存时只在聊天里点评，内容同样按下面写。复盘和模拟各自特有的部分见[面试复盘](interview-review.md#逐题复盘)和[模拟面试](mock-interview.md#点评直白直击要害)。

## 整体评价

放在逐题之前，每块都要有：

- **一句话结论：**按本轮的标准说，例如“按业务一面的要求……”。
- **标签统计：**三种处理标签各几题，三种都写（没有的写 0），与题数一致。
- **最突出的优点、最要害的问题：**分开写，各带小标题，各一两条，每条附题号；问题要说明对面试官判断的影响。
- **先改这三题：**从需补强和要重练的题里选，每题附为什么先改；不足三题有几题写几题，全部答得好就整块不写（标题和列表都不要）。

报告只给文字评价：不打分、不给总评等级，不用“及格”“几分”这类说法，不预测录用或面试结果，不凭回答评判人格或潜力。处理标签只给练习排优先级，不是分数或等级。

模拟点评在整体评价之后加覆盖情况表，列为 能力｜类型｜在哪题考到｜表现，计划内没考到的写“未考到，未知”。

## 逐题点评

**一个主问题一题，网页里一张卡片。**追问按实际顺序写在同一题的对话里，换了话题（例如从项目背景转到 SQL 题）才另起一题；“到岗时间可以吗”“后续还有几轮”这类事务性问答合进相邻一题或“材料与说明”，不单独成题。复盘一场 30 分钟左右的面试通常 15 到 20 张卡片；模拟一个主问题一张，通常 6 到 10 张。题号用两位数 Q01、Q02。

每题依次包含：

1. **题号、时间、问题原文：**时间只在录音或稿件提供可靠时间时写。
2. **处理标签：**每题一个，三选一，按这题里最需要处理的那一轮定；某轮追问的表现明显不同时，在那一轮旁加小标签。
   - `答得好`：方向和证据都到位，保留。
   - `需补强`：方向对，但缺关键证据、跳步或没答全。
   - `要重练`：答错、没回应问题，或说不清又编不圆。
3. **面试官想考察：**每题都写，一到两项，例如“个人贡献的边界”“数据口径意识”“把旧经验迁移到新场景”，由问题和本轮侧重推断，不写成面试官的内心想法。
4. **你的回答：**按顺序写出每一轮的完整回答，只删口头语、重复和与点评无关的枝节，删处用“……”，不改意思，不能只摘一句；个人贡献、数字和不确定性都保留。后面点评到的每一处都要在这里看得到：值得保留的说法和有问题的说法分别标出，有问题的按出现顺序编号（Markdown 在原话旁标 ①②③，网页用 `<sup>` 里的数字）。每一处影响判断的说法都要标，例如自我介绍里念课程和证书、优点说得空、报了说不清口径的数字，是三处。
5. **好在哪：**具体做法。答得好的题必须写，其他题有就写。
6. **问题在哪：**按编号逐条写缺什么、为什么影响判断，通常 1 到 3 个：漏答、答非所问、证据缺口、逻辑跳步、贡献边界、知识错误或表达问题，例如“铺垫了很久背景，没回答为什么选这个方案”，不只写“结构不够好”。
7. **讲圆满（可选）：**只在回答有归属疑点时写，说明怎样在真实范围内讲完整，方法见[把事情讲圆满](answer-coaching.md#把事情讲圆满)。
8. **改进后的答法：**按[可练回答规则](answer-coaching.md)写一段可以直接说出口的完整回答，只用已确认的事实或对清晰原答的忠实整理，建议做法写成“如果”“下次”，缺的事实单列请用户补充。有追问时，每个追问的答法另起一段，段首加粗写追问原文，后面直接接回答。答法里只有回答本身：不写“候选人：”“面试官：”“追问：”“你：”这类说话人标签，同一句话不重复出现。
9. **改了什么：**按编号逐条写「左栏同号标记的原话」→「改进答法里对应的新说法」：为什么这样改。同号的标记、问题和改动说的是同一处原话，新说法取自改进后的答法；“明确边界”“补充依据”这类看不出改了哪句话的概括不算一条。答得好的题不写这一项，改写“还能更好的一处”：「原话」→「更好的说法」：为什么，更好的说法同样写进改进后的答法，不为显得改过而重写。
10. **下次怎么练：**一个练习动作或可能的追问。需补强和要重练的题必须写，答得好的题可写可不写。

**反问环节**提问的人是候选人：候选人的问题标“你”，面试官的回答标“面试官回应”，不当成追问。点评的是提问本身：问题有没有价值、能不能帮自己判断岗位；改进后的答法只写更好的提问。

## 页眉与结尾

页眉只写岗位、轮次、日期、材料来源和评价基准，不写技能名或版本号。

结尾依次三块，两种报告、两种格式标题相同：

1. **下一轮怎么准备：**一两个最该准备的点，依据不足时说明。
2. **可以写进简历的新素材：**表格四列：来源题号与原话｜对应经历｜候选改写｜确认状态，每行四项都写。来源写成“Q07 “原话””，原话照抄该题左栏，数字和单位不改，改写放第三列；状态写“待确认”或“已确认”。没有就写“无”，不留只有表头的空表。
3. **材料与说明：**材料来源、转写的不确定处、没计入的部分。

Markdown 报告另有一节记录文件路径和读回结果（复盘叫“保存与修改结果”，模拟叫“文件”），网页没有这一节。网页和 Markdown 要一致的是题目和题号、处理标签、每题的点评内容和整体评价。

## 网页版怎么呈现

复用[面试报告网页模板](../assets/interview-report.html)。占位符是 `{{document_title}}`、`{{header}}`、`{{overview}}`、`{{questions}}`、`{{closing}}`，每个只出现一次，全部替换。照模板注释的嵌套示意生成，类名和结构不改，正式报告删除注释。

- 原话、问题和用户材料先转义成文本，再由自己加 `<mark>`、`<sup>`、`<strong>` 等已知标签，不把材料原样当 HTML 插入。
- 卡片类名与标签一致：`qcard good`、`qcard improve`、`qcard redo`；标签用 `chip good`、`chip improve`、`chip redo`，文字分别为“答得好”“需补强”“要重练”。
- 左栏每一轮一段，第一行用 `p.who` 写说话人，面试官的追问或回应用 `turn ask`；保留的说法用 `<mark class="keep">`，有问题的用 `<mark class="fix">`，末尾加 `<sup>` 编号。右栏每部分带 `<h5>` 小标题，顺序同上面的字段，没有内容的部分整块删掉。
- `需补强`和`要重练`的卡片默认展开；`答得好`的卡片默认收起，只露出题目和标签。
- 模拟点评的覆盖情况表写在整体评价的替换内容里、`section.panel` 之后：`<h2>覆盖情况</h2><table>…</table>`。
- 不引用外部脚本、字体或图片，单个文件即可打开。模板自带的小段脚本保留：通过链接跳到某张卡片时自动展开它，打印前展开全部卡片。
- 文件与 Markdown 报告同名，只换扩展名，例如 `interviews/<日期>-<公司>-<轮次>.html`。

## 交付前检查

运行[检查脚本](../scripts/check_interview_report.py)：`python3 scripts/check_interview_report.py <报告.html>`（路径相对技能目录）。它默认找旁边的同名 `.md` 比对题号和标签，`--type review|mock` 指定报告类型。退出码 0 没有错误，1 有错误，2 无法运行。错误修完再运行，到 0 错误才交付；提醒是启发式判断，逐条看一眼再决定。

脚本查不了、仍要自己看的：

- 实际渲染：宽屏下左右两栏并排，窄屏下上下排列。
- 同号的标记、问题和改动是否真说同一处；左栏有没有漏标的问题说法，是不是完整回答，删节有没有改意思。
- 追问是否在所属卡片里、换了话题是否另起，事务性问答是否已合并；反问环节里候选人的问题有没有被整理成面试官的话。
- 标签定得对不对；考察点、点评和改进答法是否正确，改进答法是否只用已确认的事实；结论是否按本轮标准，优点和问题是否说清了影响，“先改这三题”的理由是否成立。
- 网页与 Markdown 除题号和标签外的内容是否一致；页眉是否齐全准确；原话是否先转义再加标记。

没有 Python 时，自己逐张核对最容易错的结构：没有残留 `{{` 和注释；左栏编号与“问题在哪”“改了什么”一一对应，“改了什么”每条都引用原话和新说法；改进答法没有说话人标签，反问环节说话人没标反；标签统计与卡片数一致，答得好收起、其余展开，“先改这三题”的链接跳得到。

交付时聊天先给网页链接，再给整体评价和最该先改的一题。

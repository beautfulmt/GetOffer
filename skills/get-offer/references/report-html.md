# 面试报告的网页版

面试复盘和模拟面试点评保存时，同时交两份：Markdown 报告留作记录和后续引用，网页版给用户看。网页版把每道题的原答放在左边、改法放在右边，用户一眼能看出哪里答得好、哪里要改、怎么改。不保存时只在聊天里给，不生成文件。

## 每道题怎么呈现

每道题一张卡片，追问单独成卡、放在所属问题下面，不和主问题合并成一段。卡片内容与 Markdown 报告一致：

- **题号、时间、问题原文：**时间只在录音提供可靠时间时写。
- **处理标签：**三选一，标在题目右边，用来排练习优先级：
  - `答得好`：方向和证据都到位，保留；右栏仍给一处能更好的地方。
  - `需补强`：方向对，但缺关键证据、跳步或没答全。
  - `要重练`：答错、没回应问题，或说不清又编不圆。
  标签只说明这题下一步怎么处理，不是分数或等级，整场不给总评等级。
- **面试官想考察：**每题都写，一到两项，例如“个人贡献的边界”“数据口径意识”“把旧经验迁移到新场景”。由问题和本轮侧重推断，不写成面试官的内心想法。
- **左栏“你的回答”：**原话摘录，可删口头语和重复，删处用“……”，不改意思；回忆稿注明原话可能有出入。值得保留的说法用 `<mark class="keep">` 标出，有问题的说法用 `<mark class="fix">` 标出，并编号。
- **右栏“怎么改”：**每部分带小标题，没有内容的部分整块删掉。
  1. 好在哪：具体做法，答得好的题必须有。
  2. 问题在哪：按左栏的编号逐条写，每条说清缺什么、为什么影响判断。
  3. 改进后的答法：可以直接说出口的完整回答，只用已确认的事实；建议做法写成“如果”“下次”，不写成做过的事。
  4. 改了什么：原来怎么说 → 现在怎么说，以及为什么这样改。答得好的题写“还能更好的一处”。
  5. 下次怎么练：一个练习动作或可能的追问。

页面开头是整体评价：一句话结论、三种标签各几题、最突出的优点和最要害的问题，以及“先改这三题”的跳转链接。页面结尾是下一轮怎么准备、可写进简历的新素材和材料说明。模拟面试点评另加覆盖情况表。

## 用模板生成

复用[面试报告网页模板](../assets/interview-report.html)。占位符是 `{{document_title}}`、`{{header}}`、`{{overview}}`、`{{questions}}`、`{{closing}}`，每个只出现一次，全部替换。模板注释里有填好的嵌套示意，照着生成，正式报告删除注释。

- 原话、问题和用户材料先转义成文本，再由自己加 `<mark>`、`<sup>` 等已知标签，不把材料原样当 HTML 插入。
- 卡片类名与标签一致：`qcard good`、`qcard improve`、`qcard redo`；标签用 `chip good`、`chip improve`、`chip redo`，文字分别为“答得好”“需补强”“要重练”。
- 页面不引用外部脚本、字体或图片，单个文件即可打开。
- 文件与 Markdown 报告同名，只换扩展名，例如 `interviews/2026-11-22-澄言智能-业务一面.html`。

## 交付前检查

- 实际打开或渲染页面，看宽屏下左右两栏并排、窄屏下上下排列，没有残留 `{{`。
- 每道题都有考察点、标签、左右两栏；左栏的编号和右栏的问题一一对应；追问没有被合并掉。
- 标签计数与卡片数一致，“先改这三题”的链接能跳到对应卡片。
- 网页和 Markdown 报告内容一致。聊天先给网页链接，再给整体评价和最该先改的一题。

# 面试报告的网页版

面试复盘和模拟面试点评保存时，同时交两份：Markdown 报告留作记录和后续引用，网页版给用户看。网页版把用户的原答放在左边、改法放在右边，用户一眼能看出哪里答得好、哪里要改、怎么改。不保存时只在聊天里给，不生成文件。

## 每道题怎么呈现

**一个主问题一张卡片。**追问写在同一张卡片左栏的对话里，按实际顺序排列；追问换了话题（例如从项目背景转到 SQL 题）才另起一张卡片。“到岗时间可以吗”“后续还有几轮”这类事务性问答合进相邻卡片或结尾说明，不单独占一张。一场 30 分钟左右的面试，通常 15 到 20 张卡片。

每张卡片包含：

- **题号、时间、问题原文：**时间只在录音提供可靠时间时写。
- **处理标签：**整张卡片一个，三选一，标在题目右边，用来排练习优先级：
  - `答得好`：方向和证据都到位，保留。
  - `需补强`：方向对，但缺关键证据、跳步或没答全。
  - `要重练`：答错、没回应问题，或说不清又编不圆。
  卡片标签按这题里最需要处理的那一轮定。某轮追问的表现明显不同时，在左栏那轮回答旁加小标签。标签只说明这题下一步怎么处理，不是分数或等级，整场不给总评等级。
- **面试官想考察：**每题都写，一到两项，例如“个人贡献的边界”“数据口径意识”“把旧经验迁移到新场景”。由问题和本轮侧重推断，不写成面试官的内心想法。
- **左栏“你的回答”：**写出每一轮的完整回答，只删口头语、重复和与点评无关的枝节，删处用“……”，不改意思；不能只摘一句。右栏点评到的每一处，左栏都要能看到并标出来。值得保留的说法用 `<mark class="keep">`，有问题的说法用 `<mark class="fix">` 并编号。回忆稿注明原话可能有出入。
- **右栏“怎么改”：**每部分带小标题，没有内容的部分整块删掉。
  1. 好在哪：具体做法。答得好的题必须写，其他题有就写。
  2. 问题在哪：列出所有影响判断的问题，通常 1 到 3 个，按左栏编号逐条写缺什么、为什么影响判断。不只挑一个：左栏里每一处有问题的说法都要标出并编号，例如自我介绍里念课程和证书、优点说得空、报了说不清口径的数字，是三个问题。
  3. 改进后的答法：可以直接说出口的完整回答，有追问时连追问的答法一起写；只用已确认的事实，建议做法写成“如果”“下次”，不写成做过的事。只写回答本身，不夹带“候选人：”“面试官：”之类的标签或别处复制来的句子。
  4. 改了什么：按问题编号逐条写，每条引用原话和新说法：「左栏同号标记的原话」→「改进答法里对应的新说法」：为什么这样改。同号的问题、标记和改动说的必须是同一处原话；不写“明确边界”“补充依据”这类只有概括、看不出具体改了哪句话的条目。答得好的题写“还能更好的一处”，同样引用原话。
  5. 下次怎么练：一个练习动作或可能的追问。

**反问环节**提问的人是候选人：左栏里候选人的问题标“你”，面试官的回答用 `turn ask` 标“面试官回应”，不把候选人的问题当成追问。右栏评的是提问本身：问题有没有价值、能不能帮自己判断岗位；改进答法只写更好的提问。

`需补强`和`要重练`的卡片默认展开；`答得好`的卡片默认收起，只露出题目和标签，点开能看到原答和“还能更好的一处”。

## 整体评价和结尾

页面开头的整体评价按模板的块写，每一块都必须有：

- 一句话结论，按本轮的标准说。
- 标签统计：三种标签各几张卡片，与卡片数一致。
- “最突出的优点”和“最要害的问题”两块，各带小标题，每条附题号。
- “先改这三题”：每题一个跳转链接，加一句为什么先改。

结尾依次是：下一轮怎么准备；可以写进简历的新素材（表格：来源题号与原话、对应经历、候选改写、确认状态）；材料与说明（材料来源、转写的不确定处、没计入的部分）。模拟面试点评在整体评价后加覆盖情况表。页眉只写岗位、轮次、日期、材料来源和评价基准，不写技能名或版本号。

## 用模板生成

复用[面试报告网页模板](../assets/interview-report.html)。占位符是 `{{document_title}}`、`{{header}}`、`{{overview}}`、`{{questions}}`、`{{closing}}`，每个只出现一次，全部替换。模板注释里有填好的嵌套示意，照着生成，类名和结构不自行改动，正式报告删除注释。

- 原话、问题和用户材料先转义成文本，再由自己加 `<mark>`、`<sup>` 等已知标签，不把材料原样当 HTML 插入。
- 卡片类名与标签一致：`qcard good`、`qcard improve`、`qcard redo`；标签用 `chip good`、`chip improve`、`chip redo`，文字分别为“答得好”“需补强”“要重练”。
- 不引用外部脚本、字体或图片，单个文件即可打开。模板自带的小段脚本保留：通过链接跳到某张卡片时自动展开它，打印前展开全部卡片。
- 文件与 Markdown 报告同名，只换扩展名，例如 `interviews/2026-11-22-澄言智能-业务一面.html`。

## 交付前检查

逐项实际检查，不靠印象：

- 实际渲染页面：宽屏下左右两栏并排，窄屏下上下排列；没有残留 `{{` 和模板注释。
- 卡片数在合理范围；事务性问答没有单独成卡；追问在所属卡片的左栏里。
- 每张卡片都有考察点和标签；左栏是完整回答而不是一句节选。
- 逐张卡片核对编号：左栏的 `fix` 标记、“问题在哪”和“改了什么”编号一一对应，而且同号三处说的是同一句原话；左栏里还有没标出的问题说法就补上。“改了什么”每条都引用了原话和新说法。
- 改进答法里没有残留的说话人标签或重复句子；反问环节的说话人没有标反。
- `答得好`的卡片收起，其余展开；标签统计与卡片数一致；“先改这三题”的链接能跳到对应卡片并展开它，且都有理由。
- 网页和 Markdown 报告内容一致。聊天先给网页链接，再给整体评价和最该先改的一题。

# 可投递简历交付

用户要求完成、定制或修改整份简历，内容已可用且允许保存时，默认把可投递文件做完；不等用户再问“能导出吗”。只要分析、局部改句、待确认草稿或明确指定格式时，按本轮范围交付。

## 何时导出与交哪一版

- 导出时机只看本节：整份简历内容可用，且用户要求完成、定制或修改整份简历，或确认回写、赶投递时导出；仍在收集素材时先更新工作稿。
- 当前目标岗位已明确时，默认只导出本轮岗位版的PDF和DOCX；通用源稿作为复用材料保留，不同时再导出一套通用文件。没有目标岗位时交通用版。用户明确要两版、多岗位或特定格式时按要求完成。
- 正在收集经历或连续修改草稿时先更新工作稿和必要记录，等当前阶段可用后再导出。已经明确要求最终文件、确认回写后重新导出或赶投递时，直接完成当前版本，不以“等阶段结束”为由延后。
- 正式交付后发生本轮授权的新修改，生成当前岗位的新版本；无需重新导出未变化的其他岗位或通用版。

## 出稿条件

- 个人身份、教育或相关背景及核心经历足以形成完整简历；必要联系渠道由用户提供，也可由用户明确选择不公开。缺少会使投递无法使用的信息时集中问一次，先交付已有正文，不编造联系方式。
- 可选成绩、照片、数字和弱相关栏目可以省略。事实冲突影响的主张删除后仍可准确呈现时，继续交付；尚有关键冲突的部分不能标成可直接投递。
- 简历正文只放求职内容，来源编号、内部标签、待确认问题、修改说明和模板指令放到单独记录中。示范材料始终保留虚构身份，不用于实际投递。

## 格式与版本

- 按用户需要的格式分别选工具。一种格式成功后，仍须处理另一种被请求的格式；只要一种格式时不额外导出另一种。无需为此安装大型依赖、索取密钥或上传到外部转换站。

  | 格式 | 首选 | 该格式首选不可用时 |
  |---|---|---|
  | PDF | 宿主现有文档或PDF能力 | 可用的无头浏览器打印[墨蓝 HTML 模板](../assets/resume-navy.html)，例如 `chrome --headless --no-pdf-header-footer --print-to-pdf=<目标>.pdf <页面>.html`，随后实际核对纸张、文字提取和字体 |
  | 可编辑DOCX | 宿主现有文档生成能力 | 本机已有的DOCX工具；macOS可使用 `textutil -convert docx`。其产物没有 `word/styles.xml`，且未设 A4 和中文 `eastAsia` 字体，渲染时中文可能不可见；需补写样式、`w:eastAsia` 字体和 A4 的 `sectPr` 后重新渲染核对，仍有样式缺失就如实说明降级 |

  浏览器打印成功只完成PDF，不代表DOCX已完成，也不阻止继续调用textutil。只有PDF能力可用时，同样单独查找DOCX能力；不得因“文档或PDF技能可用”就跳过另一种格式。
- Markdown源稿与所交付的PDF、DOCX保持同一内容版本。正常导出保持视觉层级一致；textutil等降级路径如未保留样式或纸张设定，须说明实际差异。可用现有工具修复样式和A4设定后重新渲染，但不能把未经核验的降级文件称为同样式成品。源稿保留以便后续修改。
- 导出过程中产生的临时文件（页面截图、提取的正文、构建脚本、失败稿）放在临时目录，核验完成即清理，不留在个人数据目录里，避免混入用户文件或被提交进 git。
- 国内校招默认 A4，简洁单栏，优先一页；英文和海外投递依据明确的岗位要求选择，不能把所有英文简历都设为 Letter。用户指定的纸张和页数优先。
- 内容较多时先删重复与弱相关内容，再调整合理间距；不靠极小字号、裁切、隐藏正文或整体缩印挤进一页。一页无法保持可读性时说明取舍：用户未限定页数可自然分成多页，明确限定一页时继续精简内容，而非静默增页。
- 新建或重新排版默认使用[墨蓝商务样式](resume-style.md)及其可复用模板；用户指定样式或要求保留原格式时优先遵守。
- 文件名为 `resumes/<通用版|公司-岗位>-v<N>.<扩展名>`，源稿、PDF、DOCX 同版本同主名；新版本递增 N，旧稿保留。进度记录只指向检查完成的当前版本。
- 旧版的 `通用版.md`、`<公司>-<岗位>.md` 不需要批量改名，下次交付该岗位时按新名生成新版本，旧文件保留。
- 已有历史文件可保留原路径或沿用既有历史目录，不为统一目录移动用户文件或打断旧链接。修改理由沿用已有记录，不在每轮额外生成一份说明文档。

## 以实际成品核验

1. 检查文件确为 DOCX/PDF，打开或渲染实际文件，核对纸张、页数、实际视觉样式、字体、换行、边距和有无裁切重叠。不能只确认文件生成成功或标题变成蓝色。
2. 提取正文与源稿逐段比对，检查数字、日期、姓名、岗位和贡献边界。忽略合理空白和项目符号差异，不忽略事实变化。
3. 检查 PDF 中文文字可选择、复制及提取，避免整页图片冒充文本简历。用能解析 CID 字体的工具核对（macOS 可用 PDFKit 或预览的复制功能），不要用只读原始字节流的简单方法——Identity-H 编码下正文正常也会显示为乱码；提取后出现错字或部首替代时更换字体重新导出，不能只确认存在文字层。条件允许时检查字体嵌入。DOCX 使用常见可用字体，实际渲染检查分页；系统缺少思源黑体或微软雅黑时，用 Arial Unicode MS 等本机可用的中文字体并在交付说明中注明。
4. 发现缺字、漏段或分页问题就修复并复查。若宿主只能生成其中一种格式，先交付实际通过检查的文件及可编辑源稿，明确另一格式缺少什么能力；只有 Markdown 时如实交付 Markdown。未检查的格式不称为验证通过。

## 对用户怎么交付

每次正式交付更新[材料入口](../assets/materials-template.md)中的当前文件；旧版和过程资料保留在次要位置，不把同一格式的历史版混在当前文件中。只有源稿或部分格式可用时明确状态，不链接不存在或尚未检查的文件。

聊天先给当前需要的投递PDF与可编辑文件，再简述主要修改和一个必要待办；默认不将通用版、历史版、源稿、QA文件一起当附件列出。材料较多时附材料入口，用户明确要源稿或全部版本时照常给出。文件必须实际存在、可打开，不能只贴文件名。检查明细留在记录中，聊天只简要说明已检查分页和文字；没有待办就结束。

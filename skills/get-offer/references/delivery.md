# 可投递简历交付

用户要求完成、定制或修改整份简历，内容已可用且允许保存时，默认把可投递文件做完；不等用户再问“能导出吗”。只要分析、局部改句、待确认草稿或明确指定格式时，按本轮范围交付。

## 出稿条件

- 个人身份、教育或相关背景及核心经历足以形成完整简历；必要联系渠道由用户提供，也可由用户明确选择不公开。缺少会使投递无法使用的信息时集中问一次，先交付已有正文，不编造联系方式。
- 可选成绩、照片、数字和弱相关栏目可以省略。事实冲突影响的主张删除后仍可准确呈现时，继续交付；尚有关键冲突的部分不能标成可直接投递。
- 简历正文只放求职内容，来源编号、内部标签、待确认问题、修改说明和模板指令放到单独记录中。示范材料始终保留虚构身份，不用于实际投递。

## 格式与版本

- 优先调用宿主现有的文档与 PDF 技能或工具。生成同一内容版本的 PDF 和 DOCX；保留 Markdown 源稿以便后续修改。无需为了导出安装大型依赖、索取密钥或上传到外部转换站。
- 国内校招默认 A4，简洁单栏，优先一页；英文和海外投递依据明确的岗位要求选择，不能把所有英文简历都设为 Letter。用户指定的纸张和页数优先。
- 内容较多时先删重复与弱相关内容，避免靠极小字号挤进一页；一页无法保持可读性时说明取舍，用户未限定页数可采用合理页数，明确限定时继续压缩而非静默增页。
- 文件名包含候选人、公司岗位或通用版、版本号；安全化路径字符。PDF、DOCX、源稿版本一致，旧稿可恢复。进度记录只指向检查完成的当前版本。

## 以实际成品核验

1. 检查文件确为 DOCX/PDF，打开或渲染实际文件，核对纸张、页数、字体、换行、边距和有无裁切重叠。
2. 提取正文与源稿逐段比对，检查数字、日期、姓名、岗位和贡献边界。忽略合理空白和项目符号差异，不忽略事实变化。
3. 检查 PDF 中文文字可选择、复制及提取，避免整页图片冒充文本简历；条件允许时检查字体嵌入。DOCX 使用常见可用字体，实际渲染检查分页。
4. 发现缺字、漏段或分页问题就修复并复查。若宿主只能生成其中一种格式，先交付实际通过检查的文件及可编辑源稿，明确另一格式缺少什么能力；只有 Markdown 时如实交付 Markdown。未检查的格式不称为验证通过。

## 对用户怎么交付

先给投递 PDF 和可编辑文件链接，再用短句说明主要修改和需要用户处理的事项。没有待办就结束，避免强行加问。必要限制只说一次，检查明细留在记录中。交付不包含代投、外发或自动联系招聘方。

# 简历源稿模板

下面代码块里是简历 Markdown 源稿的骨架，[PDF 脚本](../scripts/build_resume_pdf.py)能直接解析，源稿写法以脚本 `--help` 为准。成稿时只保留真实内容：删掉用不上的栏目、条目和示意文字，任职类经历每段从三种写法里选一种（见[经历组织规则](../references/resume-structure.md)）。条数和每条的写法以[投得出去的简历](../references/resume-builder.md#投得出去的简历是什么样)为准。

- 姓名下一行是目标岗位，再下一行是联系方式和到岗信息，用“｜”分隔；到岗时间和地点只写用户确认过的。`>` 开头的稿件提示只在待补稿里保留。
- 栏目名决定条目怎么排：含“教育”的栏目，条目下的段落是补充信息；含“项目”“竞赛”“作品”等的栏目，条目头整行作标题；其余栏目按任职排，公司名一行，实际岗位在下一行。
- 待补稿里缺的事实写成 `[待确认：补什么]`。演练材料在末尾加单独一行 `---`，下面写虚构提示，最终版用脚本的 `--final --sample` 检查。

```markdown
# 姓名

目标岗位

电话｜邮箱｜所在城市｜可到岗时间与每周天数

> 待补草稿，空位补齐前勿投递

## 教育背景

### 学校｜专业与学历｜2023.09 至 2027.06

相关课程、排名或绩点、奖学金，真实且有利时才写。

## 实习经历

### 简单经历的公司｜实际岗位｜2025.07 至 2025.09

- 场景或对象，本人的动作和方法，对应产物或结果。
- 缺的事实留成 [待确认：补什么]。

### 多主题经历的公司｜实际岗位｜2025.01 至 2025.06

职责范围：一句话交代负责的业务或环节。

- **主题一**：这件事里本人的动作与对应结果。
- **主题二**：另一件事里本人的动作与对应结果。

### 复杂任职的公司｜实际岗位｜2024.07 至 2024.12

职责范围：一句话交代真实工作边界。

#### 关键项目名称

- 任务、本人做法与对应交付、采纳或有来源的数据。
- 另一项重要的个人贡献。

## 项目经历

### 项目名称｜实际角色｜2024.03 至 2024.06

- 发现的问题、本人的改动或方法，以及交付物和实际使用情况。

## 技能证书

- **数据**：工具或技能，写明在哪段经历里用它做了什么、实际程度。
- **语言**：证书与分数。
```
